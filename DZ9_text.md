# 1.1
## Вопрос 1
Метод принимает `List<IDamageable>` так как его цель - обработать любой объект, которому можно нанести урон. С точки зрения полиморфизма: одна и та же строчка кода `target.TakeDamage(damage)` вызывает разные методы в зависимости от реализации интерфейса.

## Вопрос 2
Ничего странного в реализации интерфейса нет, интерфейс только обязывает иметь метод `bool TakeDamage(int amount)`, но не обязывает уменьшать `HP`. Но единственная странность в том, что у нас имеется значение HP, которое не используется, что можно назвать "странным".

## Вопрос 3
Вообще не получилось бы скомпилировать такой код, так как `ProcessDamage` принимает только `IDamageable`. Но если бы мы сделали зелье `IDamageable`, то это могло бы привести например к проблемам с UI, то есть UI не сможет понять что мы вылечили героя или нанесли урон, если мы конечно не будем вносить уточняющие параметры в например событие `event`.

## Вопрос 4
Если мы это сделаем, то нужно будет добавить реализацию этого свойства у `Player` и `Trap`. Если этого не сделать, то код не скомпилируется, будет требовать реализовать свойство.

| Утверждение                                   | Abstract class | Interface | Объянение |
| --------------------------------------------- | -------------- | --------- | --------- |
| Может содержать поля с конкретными значениями | +              | -         | Абстрактный класс - класс с конкретными полями, интерфейс - только контракт                                                     |
| Может иметь полноценный конструктор           | +              | -         | У абстрактного класса - конструктор, который можно использовать в наследниках, а у интерфейса нет экземпляров и конструкторов |
| Один класс может наследовать/реализовывать несколько таких типов | - | +   | В C# нет множественного наследования, но можно реализовывать несколько интерфейсов, так как это не классы |
| Может содержать реализацию метода по умолчанию | + | +                     | C С# 8.0 интерфейсы могут реализовывать методы по умолчанию |
| Может объявлять свойства без реализации | + | + | В абстрактном классе есть `abstract`, в интерфейсе - реализация не предусмотрена |
| Может быть использован как тип поля или переменной | + | + | Оба могут использоваться таким образом, абстрактный класс ссылается на наследника, интерфейс - на класс с его реализацией |
| Может наследовать классы | + | - | Только класс может наследовать классы |
| Может содержать приватные методы | + | +? | Есть методы по умолчанию в интерфейсах, к которым можно приписать private |
